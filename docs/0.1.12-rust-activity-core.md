# 0.1.12：可选 Rust 活动核心与四项优化

**三个成品包各自安装：TS / Python / Rust，共用同一界面。** Rust 成品包附带平台 executable，无需用户编译；不会运行时自动安装 Rust、编译或下载。共享源码入口默认 TS，独立 Python/Rust 包在交互会话默认启动各自后端。本文不代表用户 macOS 实际宿主或真实终端会话验收已完成。

## 范围与默认行为

- 默认仍是 TS；Python 后端保留。
- Rust 仅计算首行活动状态、帧、短语、旁白、并行工具和完成统计。
- 轨迹原始参数/结果/消息/签名/Schema、详情、搜索、回放、持久化计时、主题和 TUI 继续留在 TS/Pi。
- 同步 TS 镜像持续更新，worker 失败及时回退；未删镜像来制造性能收益。
- `/pitools core rust` 或 `PITOOLS_CORE=rust` 显式启用。`PITOOLS_RUST_CORE` 指向可信可执行文件绝对路径（或用户显式指定的 PATH 名称）；也支持包内 `bin/<target>/pitools-core[.exe]`。
- 不自动下载、安装、编译、重启或切换默认核心。找不到 binary 则提示并继续 TS。
- 独立 stdin/stdout UTF-8 JSONL、最小环境、参数数组、`shell:false`、临时 cwd；无网络或监听端口。worker 不是权限沙箱。

## 四项联动优化

### 1. 特性协商的紧凑 delta 批次

Rust ready 宣告 `delta_pack_v1`；只有识别此特性的 Rust 后端使用新编码。旧 Rust/Python 或无特性 worker 保留原来的 `event_batch`/单事件格式。

```json
{"protocol":1,"type":"delta_pack","groups":[
  {"epoch":1,"kind":"text_delta","local":[2026,4,17,5,12],
   "texts":["⏵ 检查补丁"],"rows":[[10,1700000000000,0],[11,1700000000001,0]]}
]}
```

- 每个 group 仅共享完全相同的 epoch/kind/local；变化即形成下一有序 group。
- rows 是 `[seq, now, textIndex]`。文本表按 JS 字符串精确比较，允许孤立代理项；重复文本可以引用同一项，但**每个业务事件仍单独存在并按原顺序应用**。
- local 在入队时复制，不能被上游之后的数组修改影响。
- 批次仍限制 **4ms nominal / 64 事件 / 64KiB**；编码前以保守 UTF-16 转义上界计预算，编码后计实际 UTF-8 字节，pending 上限 4MiB。
- 一个事件仍发送旧的 event；关键事件/查询先 flush 所有先前 delta。
- Rust 对全部组、文本引用、数量、时钟和序号先验证，再改变任何状态；不存在“先应用前半批再发现后半批坏掉”。
- stop 清空事件组、文本索引、计数、待发送数据与批次计时器。

### 2. 查询与绘制共享截止时间

- 活动查询可使用宿主 `lastPaint + 120ms` 截止时间，不再独立从上一查询重启节流窗口。
- 宿主 paint 使用距离同一截止时间的剩余时间，而非无条件再等待 120ms。
- 父进程按请求 ID 记录查询入队时的 epoch/seq，并据此标记接受视图的输入进度。
- 如果 paint 所需视图尚未到达，申请/等待现有对应查询，不额外叠一轮 paint 节流；同进度的在途查询不重复申请。
- 每次待绘制请求固定其输入进度，后续普通 delta 不无限推迟这次绘制；关键事件仍提升目标进度。绘制完成后才排队后续非紧急查询，避免按旧截止时间额外查询。
- 关键事件仍可紧急刷新，动画保持既有目标节奏；真正失败会立即使用完整 TS 状态。
- 默认 TS 不依赖 worker，新调度不改色彩、widget、快捷键或详细信息完整性。

这属于调度优化，不是凭空缩短模型内部耗时。性能测量应分别记录 handler、worker 排空、最终内存 UI paint；它们都不是完整终端 compositor/实际模型响应时间。

### 3. 单次类型化解析与减少临时分配

- 不再先解析 Header、再重新扫描整帧；同一个类型化 envelope 一次接收字段。
- 不使用 serde tagged/flattened `Content` 或 `serde_json::Value` 作为自由文本中间层。
- 多态 ID 借用 raw token，再区分整数查询 ID 与 UTF-16 工具 ID；字段顺序不作假设，重复字段拒绝。
- `JsString` 从已验证 UTF-8 的内存切片借用 `RawValue`，直接解出 `Vec<u16>`，减少 raw token 的复制。
- 输出视图使用单个 UTF-16 buffer 追加借用字段，减少动作、工具名、旁白和完成文本的克隆及拼接临时值。
- 保留严格转义验证和输出 raw JSON token，不用 unsafe 跳过 JSON 验证。

### 4. 类型化静态活动数据

- `scripts/gen-rust-assets.mjs` 从原始许可 JSON 机械生成 `assets.rs`，运行时不解析 JSON，也不读取文件。
- 35 个帧预设、短语池、UI 字符串、节日、阶梯和分语言有序动作规则用静态 UTF-16 切片表示。
- 原始数据文件不改；顺序、确定性 mixSlot、FE0E 与 BSD-3-Clause 归属保留。
- `--check` 逐字比对重生成结果；生成表带原始 JSON SHA-256，ready 提供指纹。
- 生成脚本是显式开发操作，不在加载插件或运行命令时执行。

## 字符串与边界

JS 字符串是任意 UTF-16 码元序列，含孤立高/低代理项；Rust 的 `String` 不是等价替代品。

- `JsString(Vec<u16>)` 保留原始码元，滚动尾部/切片仍与 JS 的 code-unit 操作一致。
- 合法 UTF-8 wire 内孤立码元用 `\uXXXX` 编码；拒绝裸 WTF-8/CESU-8，不自动修复。
- 严格四位 ASCII hex、非法转义/裸控制/非字符串/文本预算校验。
- 常规帧 1MiB、自由文本 65,536 码元、视图 4,096 码元；超过 worker 预算则回退 TS，不截断原始轨迹内容或工具身份。
- JS hash/32 位溢出、空白、非 Unicode `/i` 匹配、列宽 Mark 判定、toFixed、主机本地日历与 FE0E 保持兼容。
- 当前 Mark 表使用 Node 24.12.0 的 Unicode 16.0。宿主 Unicode 版本不匹配则拒绝启用此 binary 并回退 TS；不默默改变列宽语义。

## 显式开发验证

```sh
node scripts/gen-rust-assets.mjs --check
cargo test --locked --manifest-path rust/pitools-core/Cargo.toml
cargo build --release --locked --manifest-path rust/pitools-core/Cargo.toml
```

将 `PITOOLS_RUST_CORE` 设置为明确构建的可执行文件，再运行 `npm test` 和真实 host 验证脚本。未指定 Rust binary 时，真实 Rust worker 的 Node 测试会明确 skip；静态数据和纯协议测试不能替代平台实际 worker 验证。
