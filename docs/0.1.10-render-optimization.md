# 0.1.10：正文缓存与重复序列化优化

## 范围

本版本正式实现“删除工具结果页重复 JSON 序列化 + 缓存未变正文”。没有改成 Python，没有升级 Pi、修改 HUD 或改动原始会话。模块版本统一为 0.1.10。

## 实现

- 结果 JSON 在 body builder 中生成一次，renderer 复用，不再次 json(result)。保持完整输出与完整 JSON 两个视图；没有截断详情。
- 每个详情组件只保留一个正文缓存条目。命中时连 body 构造也跳过，不只是跳过高亮。
- 缓存只覆盖参数/结果、模型预览/原始内容这些内容页签。概述、计时、Schema 保持动态，不缓存进行中的时长或当前工具定义。
- 缓存 key：记录对象、内部 revision、页签、列宽、raw/渲染模式、实际主题 ANSI 指纹。
- TraceStore 的 start/end 和所有相关事件更新推进 revision；同一个 result/content 对象原地变化后收到更新事件，也能使缓存失效。不假设引用相同就是内容没变。
- 主题指纹按实际颜色/Markdown 样式生成，而不是只看稳定 Theme proxy 的身份。组件 invalidate 同样清空缓存。
- 切宽度、模式、页签、记录或 revision 变化时重建。滚动只改变视口切片；月相/标题更新不重排未变正文。
- dispose/关闭/分支恢复/reload 生命周期不保留该组件的缓存；cache miss 在构建新结果前释放旧条目。

## 缓存预算

默认最多一个条目，估算预算 8 MiB。估算包含 UTF-16 文本、行数组条目及 key 字符串/元数据开销，**不是精确 V8 heap 或进程 RSS 计数**。

超过预算仍完整渲染，只是不常驻缓存；并不截断正文或抛弃原始结果。预算限制的是衍生排版缓存，不是 Pi 原始参数/结果、整个进程内存或单次渲染峰值。

内部变更通过 Pi 生命周期/更新事件获知，不监听任意 JS 对象的无事件写入。若宿主改变内容却完全不发事件，不能声称能自动探测所有深层 mutation。

## 回归验证

- 28 项单元测试：原有核心/活动 23 项，新增缓存 key、预算超限完整返回、行开销/长 key、清理/构建异常和 record revision 5 项。
- 真实 modular/bundled 加载器，多主题/色彩模式、主屏/全屏内存终端回归。
- 集成验证使用 toJSON 计数：首次结果 render 只序列化一次，重复 render/滚动不再序列化；同引用更新、结束、raw、宽度、theme、invalidate、重新打开均正确重建。
- 模型预览缓存的流式更新仍显示新正文。
- 原有计时实时更新、持久化恢复、空思考、Schema、搜索、隐藏和异常隔离测试保持。
- 同进程 TS helper/data 热升级与混合版本 fail-fast 回归。

上述验证使用合成数据，不访问真实模型或用户凭证；最终字体/emoji 视觉以实际终端为准。Mac 0.1.10 尚未在目标机器重测，不能把以前 0.1.9 的 Mac 验证当成本版本验收。

## 正式代码对照实测

Windows i7-12700K、Node 24.12.0、Pi 1.0.2；真实 modular 加载器/Theme/组件 render，内存 UI，约 64 KiB 已完成结果、160 列。相同预热，5 次独立子进程重复，每次测 24 帧，以中位数报告：

| 指标 | 0.1.9 | 正式 0.1.10 |
|---|---:|---:|
| 每帧墙钟 | 23.77 ms | 0.83 ms |
| 每帧进程 CPU time | 25.42 ms | 1.33 ms |

该场景墙钟工作约减少 96.49%；两组完整渲染数组 SHA-256 一致，所有 10 个样本通过。测试期间另有宿主回归进程，调度/GC 波动仍存在，不应把小数精度视为机器无关的常量。

这只证明**指定不变结果详情的重复 render**收益，不是整个插件/真实会话 CPU 减少 96%，也不保证总 RSS 下降。旧版 CPU 批次范围 562–782 ms，新版 15–63 ms；短窗口 Windows CPU 计数粒度和多线程 GC 都影响统计。

原始样本保留在本机审查目录的 `performance-010-raw.json` / `performance-010-summary.json`，未上传真实用户数据。

## 本版本没有解决的事项

- 流式累计全文预处理、全文搜索/摘要重复计算、历史回放算法和原始结果字节保留策略尚未重构。
- 缺工具 end 时的持续 traceWake 条件问题另行处理，本版本不擅自补造工具结束/成功。
- 超预算正文不能命中缓存，仍可能有大结果排版成本。进一步分段渲染须保持完整数据及 Markdown 语义。

## 升级

在 shell 中只更新本插件：

```sh
pi update git:github.com/ZSY007/pitools
```

在运行中的 Pi：

```text
/reload
/pitools version
```

入口、核心、渲染、活动、数据应全部为 0.1.10。更新磁盘文件不自动替换进程内代码。不要裸跑 `pi update`，它升级 Pi 本身。
